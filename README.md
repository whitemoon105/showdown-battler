## 双打操作

- 6 选 4 时，中央只显示自己的队伍，对手阵容保留在右侧预览。点击第 1～4 只的位置按钮，再选择宝可梦；可任意顺序填写、替换或撤销，确认阵容后才提交。
- 等待服务器开战后播放登场演出，不提前将预览宝可梦放上战场。
- 选招时标明当前我方位置；单体招式按服务器要求选择敌我目标，帮助只选择可用队友。地震用“全体·含队友”提示，交换场地按原规则自动交换，无须另选不存在的目标。
- 普通选招选完即提交；双打仍须完成两只的行动及必要的目标选择，不额外弹出确认。选人预览保留确认与撤销，服务器允许时可撤销已提交的行动。
- 四只宝可梦使用独立站位，保持图像原长宽比例，再按体型与距离缩放。血条紧凑排列，双方共享场地标识各显示一组；详细信息集中到血条悬停卡。

## 组队与规则

- 点击“新队伍”即按当前规则自动生成并填入完整队伍，包含道具、招式、特性、性格与能力值，可保存出战或继续编辑；无需先挑示例或确认载入。再次点击会避开上一支相同配装。
- 生成器使用同规则配装、使用率与当前引擎合法候选组合，考虑属性覆盖与共同弱点；成队后再完整校验。无需外部 AI 账号，已有本地数据可离线生成。它提供入门队伍，不承诺竞技强度或胜率。
- 道具、招式、太晶候选同时检查当前宝可梦与全队限制，包括重复道具和格式钩子；非法导入会说明问题，允许逐项修复。
- 在组队与大厅悬停规则，可提前查看队伍规模、出场数量、等级、道具限制、继承的禁用项目及太晶限制；选择列表内也可逐项预览。

- 组队、招式来源、形态限制、特性和最终队伍校验共用打包的 Pokémon Showdown 引擎。
- 宝可梦选择器按当前规则展示可用分级，并将非法项置底禁选。单打、双打、全国图鉴采用各自分级；不适用分级的规则按可用性与使用率展示。
- 当前本地公开自组队规则共 55 项。随机队伍规则由服务器生成队伍。规则版本随安装包更新；服务器新增或修改规则时可能先于本地引擎。
- 六个槽位独立编辑；中文/英文检索，滚动分批加载，鼠标清空宝可梦和昵称。特性、性格、太晶属性用固定选项，性格显示能力增减。
- 每个宝可梦的道具、招式和特性按当前规则的该宝可梦使用率排序。推荐配装在应用前通过当前规则的官方校验。
- 等级、努力值、个体值始终可见；总额、单项上限和等级来自当前规则。第九世代通常为 510/252；Champions 能力点为 66/32；LC 等级上限为 5。

## 账号

游戏模式的登录入口使用本机账号管理。注册时先检查用户名，已注册的名字会提示更换或使用已有账号登录；完成服务器验证码验证后才保存新账号。错误会显示在当前表单，取消不会保存未验证账号。

## 推荐数据

从 Smogon 月度 chaos JSON 读取数值使用率，从 Showdown data/sets 读取示例配装。每个缓存保留精确规则 ID、来源 URL、月份和分段。内置 44 个规则快照，其中 43 个含使用率、1 个仅有示例配装；当前月份为 2026-08。界面显示实际来源和月份。

只使用同一规则 ID 的统计，不将 OU 或相邻 VGC 赛制当作其他规则的推荐。保留理由：避免切换规则后继续推荐旧分级或错误规则的数据。

先载入本地图鉴与缓存，在工作线程后台更新统计；没有独立统计时照常组队并明确提示。网络错误保留同规则缓存，过期请求不能覆盖已经切换的规则或未应用的输入。保留理由：使离线与慢网下的编辑、导航可用，避免卡死和丢失输入。

## 对战画面

- 主窗口按 16:10 等比拖动缩放，最小尺寸为 1152×720；不提供破坏该比例的最大化或全屏入口。保留理由：用户要求可调大小但保持比例，避免极端长条窗口挤压角色、血条和操作区。
- 晨光等全场光幕按战场边界铺开，精灵与光点保持原始比例；显示缩放按正确坐标换算，狭窄战场改用上下血条，操作内容可滚动查看。
- 6 对 6、6 选 4、6 选 3 使用统一镜头与紧凑布局；按稳定轮廓取景，网格、站位圈和天气共享坐标，攻击动画不会驱动镜头反复缩放。
- 登场由原生动画时间线控制一个精灵球，球到达时衔接光效、叫声和出场动作；快进与立即切换不额外播放。
- 场地采用平面透视网格、前后椭圆站位区和柔和落地阴影；远端宝可梦缩小，沿用官方对战事件驱动进场、攻击、要害和克制演出。
- 晴天、雨天、沙暴、雪／冰雹、极端天气、四种场地、空间、重力与双方顺风分开呈现；光墙、反射壁、极光幕按实际所在一方显示，结束事件会清理对应效果。
- 天气／全场效果图标固定在场地上方；双方场地效果与能力变化固定在各自血条旁。只有悬停血条约 350 毫秒才显示紧凑详情卡，汇总已知信息、能力变化、己方场地和全场状态；鼠标可移入卡片滚动阅读。未公开的对手信息不会用图鉴默认值填充。
- 对战记录可以自由翻阅，阅读历史时不跳回底部；点击“回到最新”恢复跟随。
- 静止网格仅在大小或状态变化时重绘，环境粒子按需刷新；隐藏、暂停或减少动态效果模式下停止持续重绘。

## 素材和声音

- 随包普通正面资源覆盖 1,409 个物种／形态，其中 1,356 个为多帧动画；背面收录 1,410 项，其中 1,347 个为多帧动画。来源包括神百、Showdown、PokéRogue，并补充了 118 项 WikiDex 朱紫模型动画。部分背面仍为像素动画，缺少可用动画的形态保留静态资源。
- 逐文件核对帧数与哈希，形态缺失时不借用原始形态。WikiDex 动画按原始帧转为透明 WebP，最大 320 像素、24 帧／秒，减少资源读取与解码负担；来源 URL 随文件清单保存。
- 属性使用神百的 18 属性图集；星晶使用单独的彩色标记。道具优先本地图像，未单独收录的条目使用 Showdown 官方道具图集。
- 组队图鉴、素材、已打包推荐和已有队伍可离线使用。在线大厅、登录和真人对战仍需网络。
- BGM 与音效／叫声分别调音量，统一静音保留两个设置；装饰动画响应系统减少动态效果偏好。
- 对战 BGM 使用随包的剑盾、朱紫曲目，停用原 Showdown 音乐，切换对局时按播放状态切换。

- 服务器确认开战后显示本地训练家头像、双方名字与 VS 演出，再衔接原生单球登场。结算区分胜、负、平与观战，提示不阻挡后续操作。
- 游戏模式隐藏未适配的原网页弹窗与房间，规则、队伍、登录使用本地页面或统一样式；主动选择“原版网页”时才切回网页显示。

## 网络、数据与日志

对战器固定直连，不提供本地代理设置。保留理由：避免本地代理端口依赖、端口冲突和意外代理出口。

Showdown 服务器的 IP 封锁仍由服务器决定；软件记录该提示，不能替服务器解除封锁。

本机数据位于 E:/Entertainment/AppData/ShowdownBattler，缓存位于 E:/Entertainment/Caches/ShowdownBattler。其他电脑没有该目录时使用其用户应用数据目录；不会指向大肥鱼的模型或训练目录。账号、队伍、战绩不包含在安装包中。

点击顶部“网络”可导出 JSONL 日志，包含程序版本、系统、连接/加载错误、规则 ID、数据源、耗时、槽位和错误栈。账号密码不记录到组队操作日志。反馈时附上日志、发生时间和操作步骤。

## 开发与验证

- npm start：运行客户端。
- 首次开发：安装 Node.js 22 或更新稳定版，运行 npm ci；图像和离线数据随仓库提供。Windows 打包使用 npm exec electron-builder -- --win nsis --publish never。
- npm test：规则矩阵、56 项规则读取、槽位、配装合法性、推荐缓存、资源完整性与数据隔离测试。
- npm run test:ui：真实 Electron 鼠标操作和离线检查。测试使用独立数据目录；Playwright 路径可通过 PLAYWRIGHT_PATH 指定。
- npm run test:battle：真实 Electron 对战协议回放、动画帧、鼠标悬停、天气与场地解除、滚动记录、音量和离线资源检查。
- npm run test:layout：6 对 6／6 选 4／6 选 3 在 1920×1080、1440×960、1100×720 的镜头、血条、行动区、单球登场，以及小窗口场地和要害特效回放。
- npm run test:doubles：6 选 4 位置与撤销、双目标、帮助、群攻、行动确认、天气覆盖，以及大／小窗口的血条边界检查。
- tools/sync-team-recommendations.cjs：按当前规则同步可获得的独立统计。
- tools/download-52poke-sprites.cjs：按编号和形态匹配神百图像，读取实际动画元数据。
- tools/sync-wikidex-motion.cjs、tools/optimize-motion.cjs：补充 WikiDex 对应形态动画并转换为紧凑的透明动画资源。

本轮未使用用户账号进行真实排位。测试不代表每种服务器玩法、每个招式演出都已通过真人对战验收。第三方来源见 THIRD_PARTY.md。

新增验证：`node tests/starter-ui.e2e.cjs` 检查自动生成、规则预览与缩放；`node tests/audio-results.e2e.cjs` 检查独立音量和结算。`tools/sync-sample-teams.cjs` 可维护生成候选的来源数据，`tools/sync-trainers.cjs` 同步头像及来源清单。

`node tests/window-aspect.e2e.cjs` 在 Windows 上检查原生边缘/角点缩放和最小尺寸；`node tests/battle-aspect.e2e.cjs` 刻意绕过窗口比例限制，用横长、竖长、125%/150% 缩放回放晨光与天气，检查图层边界和等比渲染。其非标准长条尺寸是诊断条件，正常拖动窗口不会进入这些比例。
